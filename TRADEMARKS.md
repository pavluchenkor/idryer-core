# iDryer Naming and Trademark Policy

This policy applies to all iDryer software repositories. The code is licensed
under the Apache License 2.0, which grants broad rights to use, modify and
sell. Section 6 of that license does not grant rights to the project name.
This document explains how the name may be used.

The intent of this policy is permissive. Community projects built on iDryer
are welcome, and several already exist. The purpose here is to keep the name
meaningful for users, not to restrict what you build.

## Summary

| What you want to do | What applies |
| --- | --- |
| Use, modify, sell the code | Apache License 2.0. No permission needed. |
| Say your project works with iDryer | No permission needed, if it is true. |
| Name your project "iDryer something" | Ask first. Usually yes. |
| Use "iDryer" to name a competing product or service | Not permitted. |

## No permission needed

You may describe your project's relationship to iDryer without asking anyone,
**provided the statement is accurate**:

- "Compatible with iDryer" — only if it actually interoperates with current
  iDryer devices or the iDryer portal.
- "Based on iDryer" / "Built on the iDryer ecosystem" — only if it actually
  uses iDryer code or protocols.
- "Works with the iDryer portal" — only if it actually connects to it.

Building on the iDryer core library does not by itself make a project
compatible: a fork may diverge from the current protocol, or target hardware
the ecosystem does not support. Claim compatibility only for what your
project genuinely does, and say plainly where it differs.

An inaccurate compatibility claim is not covered by this permission. Users
who buy or build on a false claim end up asking the iDryer maintainer for
support, which is exactly the confusion this policy exists to prevent.

You may fork any repository, modify it, distribute it and sell it, under the
terms of the Apache License 2.0, provided the fork carries a name of its own.

## Ask first, and the answer is usually yes

If you want to call your project **"iDryer <something>"** — a display module,
a standalone firmware, an alternative enclosure, a community build — open an
issue or write to the maintainer. Approval is normally granted. What is being
checked is only that the name will not confuse users about what your project
is and who supports it.

Existing community projects carrying the name were approved this way.

## Not permitted

- Using "iDryer" as the name of a competing product, service, protocol,
  portal or cloud platform. Building and selling a competing device is
  permitted by the Apache License 2.0 — using this name for it is not.
- Claiming compatibility that does not exist.
- Presenting a project as official, certified or endorsed without agreement.
- Using the name in a way that implies the maintainer supports or is
  responsible for your product.

## Hardware and documentation

This policy covers software repositories. Hardware design and the iDryer X
documentation are licensed separately and are not covered by the Apache
License 2.0.

# Политика использования имени iDryer

Политика распространяется на все программные репозитории iDryer. Код
лицензирован под Apache License 2.0, которая даёт широкие права на
использование, изменение и продажу. Пункт 6 этой лицензии не передаёт прав
на название проекта. Здесь описано, как имя можно использовать.

Политика намеренно разрешительная. Проекты сообщества на базе iDryer
приветствуются, некоторые уже существуют. Цель — сохранить смысл имени для
пользователей, а не ограничить то, что вы делаете.

## Кратко

| Что вы хотите сделать | Что применяется |
| --- | --- |
| Использовать, менять, продавать код | Apache License 2.0. Разрешение не нужно. |
| Указать совместимость с iDryer | Разрешение не нужно, если это правда. |
| Назвать проект «iDryer что-то» | Спросите. Обычно да. |
| Назвать «iDryer» конкурирующий продукт или сервис | Не разрешено. |

## Разрешение не требуется

Вы можете описывать связь своего проекта с iDryer, никого не спрашивая,
**при условии, что утверждение соответствует действительности**:

- «Совместимо с iDryer» — только если проект действительно работает с
  актуальными устройствами iDryer или с порталом iDryer.
- «На базе iDryer», «Построено на экосистеме iDryer» — только если проект
  действительно использует код или протоколы iDryer.
- «Работает с порталом iDryer» — только если он к нему действительно
  подключается.

Использование библиотеки ядра само по себе совместимости не гарантирует:
форк может разойтись с актуальным протоколом или работать на железе, которое
экосистема не поддерживает. Заявляйте совместимость только с тем, что ваш
проект действительно умеет, и прямо указывайте, в чём он отличается.

Недостоверное заявление о совместимости этим разрешением не покрывается.
Пользователь, купивший устройство по ложному заявлению, придёт за поддержкой
к мейнтейнеру iDryer — ровно та путаница, ради предотвращения которой эта
политика и существует.

Вы можете форкнуть любой репозиторий, изменить его, распространять и
продавать на условиях Apache License 2.0 — при условии, что форк носит
собственное имя.

## Спросите заранее — обычно ответ положительный

Если хотите назвать проект **«iDryer <что-то>»** — модуль экрана,
standalone-прошивку, альтернативный корпус, сборку сообщества — заведите
issue или напишите мейнтейнеру. Согласование, как правило, даётся.
Проверяется только то, что имя не введёт пользователей в заблуждение
относительно того, что это за проект и кто его поддерживает.

Существующие проекты сообщества с этим именем были согласованы именно так.

## Не разрешено

- Использовать «iDryer» как название конкурирующего продукта, сервиса,
  протокола, портала или облачной платформы. Собрать и продавать
  конкурирующее устройство Apache License 2.0 разрешает — назвать его этим
  именем нельзя.
- Заявлять совместимость, которой нет.
- Представлять проект как официальный, сертифицированный или одобренный
  без согласования.
- Использовать имя так, чтобы это подразумевало поддержку или
  ответственность мейнтейнера за ваш продукт.
