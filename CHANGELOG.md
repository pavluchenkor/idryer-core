# Changelog

Этот файл ведётся на русском языке и фиксирует заметные изменения в библиотеке `idryer-core` (общий SDK + контракт протокола для сушилки, грелки и хранилища).

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/). История до этого файла — в git-тегах (последний выпущенный: `v1.0.0`).

## Типы изменений

- **Добавлено** — для новых функций.
- **Изменено** — для изменений в существующей функциональности.
- **Устарело** — для функций, которые скоро будут удалены.
- **Удалено** — для удалённых на данный момент функций.
- **Исправлено** — для любых исправлений багов.
- **Безопасность** — на случай уязвимостей.

## [Не выпущено]

### Добавлено

- **Игнор внешних команд** (`ignore_external_cmd`): гейт команд в SDK (`Link::dispatchCommand`), canonical-роль `system.ignore_external_cmd`, отражение в `status`. Флаг кадра `UART_FLAG_LOCAL` — команды из локальной сети (WS) проходят при включённом игноре; исключения для OTA и `set`.
- **OTA по воздуху**: `OtaReceiver` в SDK (self-update прошивки ESP, для всех устройств) + поддержка **парного** обновления сушилки (RP2040 + ESP): ESP проксирует прошивку контроллера по UART, после перезагрузки — проверка совместимости (handshake) с откатом при несовпадении. OTA MQTT-топики, идентификация платы.
- Двухчиповая привязка (`bind_ack`), `mcuFirmwareVersion` / `hardwareVersion` в `info`.
- Телеметрия: температура ТЭНа (`heaterTempC10`); спец-значение «нет данных» для полей датчиков (недоступный датчик → пусто, а не ложный 0); веса — на отдельном топике.
- `MenuPublisher` и предельный размер сериализованного меню (`MENU_SERIALIZED_MAX_SIZE`); общий header `menu_commands`.
- Новые режимы на уровне SDK: `HEATING` (грелка) и `LIGHT_ANIMATION` (световая анимация — для отдельного LED-устройства, не для сушилки).
- `chamberTemp` из активной интеграции принтера; поле прогресса Bambu.
- Роль `system.air_max_temp`; scaling-aware аксессоры (DBC-стиль); генерация Dart-типов для Flutter.
- Настраиваемая мощность WiFi (`IDRYER_WIFI_TX_POWER`); публикация `timestamp` за флагом; локальный WS-протокол (приложение ↔ устройство в LAN); `WorkTimeTracker` — накопительная наработка в NVS.

### Изменено

- Крупная переработка контракта (`mqtt_contract.yaml`): чистка, матрица поддержки топиков по продуктам, конвенция °C×10 для UART-температур, унификация severity `INFO/WARN/ERROR/CRIT`.
- Детекция delta-конфига по форме JSON, а не по биту `transferId`.
- Переименование capability-флагов под `capability_vocabulary` (`hasHeater/hasFan/hasWeight`).

### Исправлено

- Удалён мёртвый legacy binary-путь `ConfigPush`.
- Буферы payload/JSON увеличены до 1024 для profile-команд.
- OTA: отложенный `set_boot_partition` до commit; drop устаревших chunks по `commandId`.
- Локальный WS: при `auth_ok` пушится не только `config`, но и `info` (built-in команда `get_info` → `publishInfoNow`). Поздно подключившийся LAN-клиент получает `mcuSerial`/`deviceType` сразу, а не ждёт события (info не retained на локальном WS).
