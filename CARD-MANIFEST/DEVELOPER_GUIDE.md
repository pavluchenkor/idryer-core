# Карточка устройства: справочник разработчика

> **Статус: проектируемый API.** Описанного здесь единого объявления в SDK пока нет —
> сегодня сущности объявляются дважды, через `ha.*` и `card().*`. Этот документ описывает,
> как это будет выглядеть после объединения. Схема манифеста — в
> `contracts/mqtt_contract.yaml`, решения — в `CARD-MANIFEST/README.md`.

---

## 1. Что вы делаете

Вы **один раз** объявляете, из чего состоит ваше устройство. Дальше SDK сам:

- публикует манифест в топик `card` — из него портал и приложение рисуют карточку;
- публикует discovery для Home Assistant — из него карточку рисует HA;
- принимает команды и зовёт ваши колбэки.

Вы не пишете JSON, не придумываете имена топиков и не разбираете входящие сообщения.

**Правило:** что объявили — то и нарисуется. Не объявили — не нарисуется нигде. Клиент не
имеет права дорисовать что-то от себя.

---

## 2. Минимальный пример

```cpp
void setup() {
  // …инициализация Link…

  auto& e = device().entities();

  // Показать температуру
  e.sensor("temp", SensorClass::Temperature, "°C", "units[0].temperature");
}
```

Всё. На карточке появится ячейка с термометром, подписью на языке пользователя и
значением из вашей телеметрии. В Home Assistant появится сенсор температуры.

---

## 3. Шаг первый: выбрать тип

| Что вы хотите | Тип | Пример |
|---|---|---|
| Показать число | `sensor` | температура, вес, мощность |
| Показать число полосой | `sensor` + `display("bar")` | прогресс сессии, загрязнение фильтра |
| Показать «да/нет» | `binary_sensor` | вентилятор крутится, заслонка открыта |
| Дать ввести число | `number` | целевая температура, длительность |
| Дать выбрать из списка | `select` | режим работы, профиль |
| Дать нажать | `button` | опознать прибор, сбросить ошибки |
| Дать включить и видеть, включено ли | `switch` | нагрев, сушка |
| Дать управлять подсветкой | `light` | лента Storage |

**Если сомневаетесь между `button` и `switch`:** спросите, есть ли у действия состояние,
которое надо показывать на экране.

- Нагрев можно застать включённым или выключенным — это состояние. Значит `switch`.
- Опознание прибора застать нельзя: пискнул и всё. Состояния нет. Значит `button`.

Так же устроено в Home Assistant: «Unlike a switch, a button has no on or off state.»
Их же примеры для кнопки — перезагрузить прибор, опознать железо.

---

## 4. Шаг второй: откуда берётся значение

Каждая сущность, которая что-то показывает, должна знать два вещи: **из какого пакета**
брать значение и **где внутри пакета** оно лежит.

```cpp
e.sensor("temp", SensorClass::Temperature, "°C",
         "units[0].temperature");        // ← путь
```

**Путь** — это адрес поля в том JSON, который прибор уже публикует. Чтобы его узнать,
посмотрите на свой хук `onTelemetryPublish`. Массив юнитов туда приходит уже готовым,
его создаёт ядро; вы только дополняете:

```cpp
static void enrichTelemetry(JsonObject root) {
  root["deviceType"] = …;            // корень — карточке НЕ виден

  JsonArray units = root["units"];   // массив уже создан ядром
  JsonObject u1 = units[0];
  u1["temperature"] = chamberT;      // → путь "units[0].temperature"
  u1["vocIndex"]    = voc;           // → путь "units[0].vocIndex"
}
```

**Источник** — из какого пакета, `telemetry` или `status`. По умолчанию `telemetry`;
если значение живёт в статусе, укажите явно. Дописывается цепочкой после объявления —
так же задаются `name`, `display`, `range`, `icon`, `unitId`, и работает это для любого
типа, не только для датчика:

```cpp
e.sensor("progress", "%", "units[0].progressPct").source(Source::Status);
```

> **Важно.** Поле должно лежать **внутри юнита**, то есть в `units[0]`, а не в корне
> пакета. Значения из корня карточка адресовать не умеет. Если сейчас вы кладёте что-то в
> корень — перенесите в юнит.

## 5. Шаг третий: принять команду

У сущностей, которыми управляют, вы указываете колбэк. Имя команды SDK придумывает сам —
`card.{id}`, — и сам зовёт ваш код:

```cpp
e.number("heat_temp", 30, 90, 1, "°C",
         [](float v) { heat_set_temp(v); });   // ← придёт новое значение
```

| Тип | Что приходит в колбэк | Когда зовётся |
|---|---|---|
| `number` | новое число | при изменении значения |
| `select` | выбранная строка | при выборе |
| `button` | ничего | при нажатии |
| `switch` | `true` / `false` | при щелчке |
| `light` | состояние, цвет, эффект | при любом изменении |

Отдельной кнопки «применить» у `number` нет — значение уходит сразу, как в Home Assistant.

Колбэк — это ваш обычный код на приборе. Никаких сообщений разбирать не надо: SDK уже
принял команду, проверил её и вызвал вас с готовым значением. Что делать дальше — ваше
дело: записать уставку, дёрнуть реле, отправить команду контроллеру по UART.

**Где хранить принятое значение.** В оперативной памяти сразу, в энергонезависимую —
отложенно, когда пользователь перестал крутить. Иначе изнашиваете NVS на каждом шаге
ползунка.

## 6. Справочник по типам

### `sensor` — показать число

```cpp
e.sensor("temp", SensorClass::Temperature, "°C", "units[0].temperature");
```

| Аргумент | Обязателен | Что |
|---|---|---|
| `id` | да | Имя внутри прибора, латиница и подчёркивания |
| класс | нет | Смысл величины: из него иконка и переведённая подпись |
| единица | нет | `"°C"`, `"%"`, `"g"` |
| путь | да | Где лежит значение |

**Имена классов в коде.** Полный список — в конце, раздел 11. Пишутся в
верблюжьем регистре: `carbon_dioxide` → `SensorClass::CarbonDioxide`,
`pm25` → `SensorClass::Pm25`.

**Класса нет в словаре — подпись обязательна.** Иначе в карточке окажется `id`, то есть
человек увидит `filter` вместо «Износ фильтра»:

```cpp
e.sensor("voc", "ppm", "units[0].vocIndex").name("VOC");          // правильно
e.sensor("filter", "%", "units[0].filterPct");                    // ← в карточке будет "filter"
e.sensor("filter", "%", "units[0].filterPct").name("Filter wear"); // правильно
```

**Полосой вместо числа:**

```cpp
e.sensor("progress", "%", "units[0].progressPct")
   .source(Source::Status)
   .display(Display::Bar).range(0, 100);
```

Полоса требует диапазона — без него непонятно, от чего считать заполнение. Единица при
этом любая, не обязательно проценты: запылённость 0..255 — это `range(0, 255)` и та
единица, в которой она измеряется. Заполнение считает потребитель.

### `binary_sensor` — показать да/нет

```cpp
e.binarySensor("fan", BinaryClass::Fan, "units[0].fanStatus");
```

Подходящего класса нет — объявляйте без него, но с подписью:

```cpp
e.binarySensor("door", "units[0].doorOpen").name("Door");
```

| Аргумент | Обязателен | Что |
|---|---|---|
| `id` | да | Имя внутри прибора |
| класс | нет | `BinaryClass::Fan` или `BinaryClass::Servo` |
| путь | да | Где лежит значение |

### `number` — поле ввода

```cpp
e.number("heat_temp", 30, 90, 1, "°C", [](float v) { heat_set_temp(v); })
   .state("units[0].targetTempC");      // чтобы поле показывало текущее значение
```

| Аргумент | Обязателен | Что |
|---|---|---|
| `id`, минимум, максимум, шаг | да | Границы ввода |
| единица | нет | Подпись справа от поля |
| колбэк | да | Куда придёт значение |
| `state(path)` | **настоятельно** | Без него поле всегда пустое |

Границы берите из меню прибора, а не константой — тогда они совпадут с тем, что человек
видит на экране устройства:

```cpp
e.number("heat_temp",
         g_menu_meta[MENU_HEAT_TEMP].min_val,
         g_menu_meta[MENU_HEAT_TEMP].max_val, 1, "°C", …);
```

### `select` — выбор из списка

```cpp
e.select("mode", {"auto", "on", "off"}, [](const char* v) { set_mode(v); })
   .state("units[0].mode");
```

От одного до восьми вариантов.

### `button` — разовое действие

```cpp
e.button("find", "Find", [] { beep_and_blink(); });
```

Состояния нет, показывать нечего. Подпись обязательна: словарного класса у кнопки не
бывает, и без подписи в карточке окажется `id`.

Настоящие кнопки в наших изделиях: опознание прибора (`find`), сброс ошибок
(`clear_errors`), подсветка слота на несколько секунд, запись RFID-метки.

### `switch` — включатель с состоянием

```cpp
e.switch_("heat", "units[0].mode", "HEATING",
          /*включить*/ [] { heat_start(); },
          /*выключить*/ [] { heat_stop(); });
```

| Аргумент | Что |
|---|---|
| путь | Откуда читать текущее состояние |
| значение «включено» | Что в этом поле означает «включено», например `"HEATING"` |

**Если в поле лежит просто `true`/`false`** — значение «включено» не указывайте, оно не
нужно:

```cpp
e.switch_("lamp", "units[0].lampOn",
          []{ lamp_on(); }, []{ lamp_off(); });
```

Третий аргумент нужен только когда состояние закодировано строкой или числом: у сушилки в
`mode` лежит `"IDLE"` или `"DRYING"`, и надо сказать, какое из них считать включённым.

Переключатель сам покажет, работает прибор или нет. Двух кнопок не нужно.

Если состояние живёт в статусе, а не в телеметрии — добавьте `.source(Source::Status)`,
как у датчика:

```cpp
e.switch_("purge", "units[0].mode", "PURGING",
          []{ purge_start(); }, []{ purge_stop(); })
   .source(Source::Status);
```

### `light` — подсветка

```cpp
e.light("led", "units[0].ledOn",
        {"solid", "breathe", "wave", "rainbow", "twinkle"},
        /*произвольный цвет*/ true,
        [](const LightState& s) { led_apply(s); });
```

В колбэк приходит всё состояние разом:

```cpp
struct LightState {
  bool        on;        // включить или выключить
  uint8_t     r, g, b;   // цвет, если объявлен произвольный
  const char* effect;    // выбранный эффект из вашего списка
};
```

Колбэк зовётся на любое изменение: щёлкнули выключателем, выбрали другой эффект, покрутили
цвет. Разбирать, что именно изменилось, не надо — применяйте состояние целиком.

Заменяет собой список анимаций, выбор цвета и две кнопки. В Home Assistant отдаётся
штатной лампой — с колесом цвета и списком эффектов без ручной настройки.

## 7. Приборы с несколькими секциями

Если у прибора больше одного юнита — две секции сушки, несколько полок — объявите сущности
для каждого и пометьте номером секции:

```cpp
for (uint8_t u = 0; u < CFG.unitsCount; ++u) {
  char id[24], path[32];

  snprintf(id,   sizeof(id),   "temp_%u", u);
  snprintf(path, sizeof(path), "units[%u].temperature", u);
  e.sensor(id, SensorClass::Temperature, "°C", path).unitId(u);

  snprintf(id,   sizeof(id),   "humidity_%u", u);
  snprintf(path, sizeof(path), "units[%u].humidity", u);
  e.sensor(id, SensorClass::Humidity, "%", path).unitId(u);

  snprintf(id,   sizeof(id),   "temp_%u", u);
  char id2[24];
  snprintf(id2,  sizeof(id2),  "humidity_%u", u);
  e.layoutRow(id, id2);
}
```

Буферы можно переиспользовать: SDK копирует строки к себе при объявлении, а не запоминает
указатель.

Два правила:

**Идентификаторы уникальны во всём манифесте.** Двух сущностей `temp` быть не может, даже
если они в разных секциях. Поэтому `temp_0` и `temp_1`, или что-то своё — главное,
различающееся.

**`unitId` обязателен, если секций больше одной.** По нему карточка группирует сущности:
секция сверху, её датчики под ней. Без него все сущности свалятся в одну кучу, и человек
не поймёт, какая температура к какой секции относится. По умолчанию `unitId` равен 0 —
для приборов с одной секцией указывать не нужно.

Раскладка `layoutRow` работает внутри секции: перечисляйте в ряду идентификаторы одной и
той же секции.

> Сегодня манифест умеет только первую секцию (`units[0]`) — многосекционность в схеме
> ещё не реализована. Раздел описывает, как это будет.

## 8. Раскладка

По умолчанию сущности идут в порядке объявления, датчики группируются по три в ряд,
элементы управления — каждый во всю ширину.

Чтобы задать ряды явно:

```cpp
e.layoutRow("temp", "humidity");
e.layoutRow("progress");
```

До 16 рядов, до 4 элементов в ряду. Сущности, не упомянутые в раскладке, дорисуются ниже
по умолчанию. Элементы управления в один ряд не сжимаются в любом случае.

Раскладка уходит только в карточку. В Home Assistant её нет — там пользователь
раскладывает сам.

## 9. Полный пример: нагреватель

```cpp
auto& e = device().entities();

// Температура камеры принтера — своего датчика нет, значение от интеграции
e.sensor("temp", SensorClass::Temperature, "°C", "units[0].temperature");

// Мощность добавится сама из Config.hasHeater — объявлять не надо

// Прогресс сессии полосой
e.sensor("progress", "%", "units[0].progressPct")
   .source(Source::Status).display(Display::Bar).range(0, 100);

// Уставки
e.number("heat_temp", tempMin, tempMax, 1, "°C", [](float v){ heat_set_temp(v); })
   .state("units[0].targetTempC");
e.number("heat_duration", 0, 600, 1, "min", [](float v){ heat_set_duration(v); })
   .state("units[0].targetDurationMin");

// Нагрев
e.switch_("heat", "units[0].mode", "HEATING",
          []{ heat_start(); }, []{ heat_stop(); });

e.layoutRow("temp", "power");
e.layoutRow("progress");
```

Получится карточка: ряд из температуры и мощности, под ним полоса прогресса, два поля
ввода и переключатель нагрева.

## 10. Частые ошибки

| Ошибка | Что будет | Как надо |
|---|---|---|
| Значение лежит в корне пакета, не в `units[0]` | Пустая ячейка | Перенести поле в юнит |
| У `number` не задан `state(path)` | Поле всегда пустое, уставка не видна | Указать путь к текущему значению |
| Две кнопки вместо `switch` | По карточке не понять, работает прибор или нет | Один `switch` с путём к состоянию |
| `display(Bar)` без диапазона | Полоса не рисуется | Добавить `range(min, max)` |
| Границы `number` заданы константой | Расходятся с меню прибора | Брать из `g_menu_meta` |
| Объявлено то, чего прибор не умеет | Кнопка есть, нажатие не делает ничего | Объявлять только реализованное |
| Подпись у сущности без класса не задана | В карточке будет `id` | Задать `name` |

## 12. Классы: как называются в коде

Слева — как пишете в прошивке, справа — во что превращается в манифесте и в Home Assistant.

### Для `sensor`

| В коде | В манифесте | Что | Единица |
|---|---|---|---|
| `SensorClass::Temperature` | `temperature` | Температура | °C |
| `SensorClass::Humidity` | `humidity` | Влажность | % |
| `SensorClass::Power` | `power` | Мощность | % |
| `SensorClass::Weight` | `weight` | Вес | г |
| `SensorClass::CarbonDioxide` | `carbon_dioxide` | Углекислый газ | ppm |
| `SensorClass::Voc` | `volatile_organic_compounds` | Летучие органические | µg/m³ |
| `SensorClass::VocParts` | `volatile_organic_compounds_parts` | Летучие органические, доли | ppm, ppb |
| `SensorClass::Pm1` | `pm1` | Частицы < 1 мкм | µg/m³ |
| `SensorClass::Pm25` | `pm25` | Частицы < 2.5 мкм | µg/m³ |
| `SensorClass::Pm4` | `pm4` | Частицы < 4 мкм | µg/m³ |
| `SensorClass::Pm10` | `pm10` | Частицы < 10 мкм | µg/m³ |
| `SensorClass::NitrogenDioxide` | `nitrogen_dioxide` | Диоксид азота | ppb, ppm, µg/m³ |
| `SensorClass::Ozone` | `ozone` | Озон | ppb, ppm, µg/m³ |
| `SensorClass::Aqi` | `aqi` | Индекс качества воздуха | — |
| `SensorClass::HeaterTemp` | `heater_temp` | Температура нагревателя ⁽¹⁾ | °C |

### Для `binary_sensor`

| В коде | В манифесте | Что |
|---|---|---|
| `BinaryClass::Fan` | `fan` | Вентилятор ⁽¹⁾ |
| `BinaryClass::Servo` | `servo` | Заслонка ⁽¹⁾ |
